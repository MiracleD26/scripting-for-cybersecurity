3. Where the break fired, and whether it cost us a match

   It fired twice, on auth.log and firewall.log, since both reached the
   three-indicator limit - each has the "stopped early" note to prove it. It
   didn't hide anything this time: running check_iocs.sh (no cut-off) over the
   same four logs gives 2, 3, 3 and 0, identical to the scan. That's because
   those two logs only ever contain the three IOC IPs, so stopping at three
   happened to land on the real total. I wouldn't rely on that though - if a
   log held four or more indicators the script would still say 3, and the
   "stopped early" note is the only sign the number is a minimum and not the
   exact count.

4. Why the exit code matters for an unattended nightly run

   If scan_all.sh ran from cron every night with nobody watching, the exit code
   is the only signal the scheduler can react to, so 1 can raise an alert or
   open a ticket while 0 stays quiet - which means someone only gets called out
   when the collection genuinely needs investigating.
